# 07 — Evaluation and Statistical Protocol

**Status:** prospective, scores not yet available.

## Primary endpoints
Compute independently for VALUE and CUE heads, never pool them without stating aggregation:
- **strict exact character-span** `precision, recall, F1`: match iff `(start,end,label)` matches exactly for the same example/layer;
- class-level supports and micro/macro F1; macro excludes classes with zero gold support and explicitly states excluded classes;
- token-level confusion (optional), reported separately from exact-span evaluation; token accuracy dominated by O is not headline.

## Secondary metrics (only when adjudicated gold exists)
- `transition_accuracy`, updated-slot accuracy, reference link precision/recall, explicit abstain/unresolved rate;
- wrong-edit rate and false positive rate on `NO_CHANGE_CONTROL`, negative cancellation and system-confirmation cases;
- exact match of complete state should only be reported if **every** required state/slot has ground truth and no inference-time oracle.

## Correctness definitions
`TP`: predicted span matches a gold span of same label and exact boundaries. `FP`: predicted span lacks matching gold. `FN`: gold span lacks match. Precision = TP/(TP+FP), recall = TP/(TP+FN), F1 = 2TP/(2TP+FP+FN). Denominator-zero scores must be recorded as `null`/`not_evaluable`, not invented perfect values. Aggregate over examples, not average only per-message F1.

## Source and split controls
- Primary custom test set: held-out, dialogue/family-grouped, adjudicated OVERRIDE spans, frozen before model selection.
- Official SGD slots and dialogue states are **not** OVERRIDE gold unless new labels were actually collected.
- Never tune on held-out challenge examples; L4/L5 with sparse labels may be diagnostic only.
- Any test chosen by heuristics must be explicitly labeled as enriched / selection-biased; it cannot estimate source population prevalence.

## Statistical practices
Report sample size, positive supports per class and per difficulty level, dataset-source shift if applicable. Where sufficient independent dialogue families exist, compute bootstrap confidence intervals by **dialogue/family**, not by tokens or windows. Compare models on identical examples. Disclose class imbalance, label disagreement, CI unreliability if tiny groups, truncation and unsupported classes.

## Robustness matrix
| Slice | What to test | Leakage/control |
|---|---|---|
| L1 explicit update | `not Berlin ... Paris` | no keyword memorization only |
| L2 partial preserve | changed count, kept date | values and cues separate |
| L3 cancel/negated cancel | `do not cancel flight; cancel hotel` | scope-aware, avoid wrong cancellation |
| L4 restore | `back to the first option` | actual resolvable historical mention |
| L5 mixed context | revert destination, keep new count | not supported unless enough gold |
| Hard negatives | confirmation; aliases; system offer; slot fill | no automatic UPDATE from state changes |

## v0.6 compulsory final-test integrity gate

For **final reported test results only**, call `scripts/evaluate_frozen_test.py` with the **full adjudicated gold**, `freeze_gold_splits.py` manifest, and test-ID-only predictions. The script verifies gold text/label SHA-256, split manifest digest, no train/dev/test ID overlap, dialogue-family membership, and exact prediction ID coverage. Direct `evaluate_spans.py` is permitted for **development diagnostics only**, never as proof of held-out final score.

The frozen manifest now reports support by class and split; unsupported test classes are NOT EVALUABLE. If key labels have zero support on test, do not claim generalization; prospectively redesign the split before any model-driven tuning and re-freeze with recorded decision.
